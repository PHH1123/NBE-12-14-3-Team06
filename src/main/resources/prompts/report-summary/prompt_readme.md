# 보고서 AI 요약 프롬프트 개선 실험 계획서

## 1. 개요

### 1.1 목적
진료 보고서 AI 요약(`ClaudeReportSummarizer`)의 시스템 프롬프트를 개선한다.
동행인이 보고서를 **짧게 쓰거나 키워드 위주로 써도** 요약이 사실을 왜곡하거나 내용을 지어내지 않는지 확인하고,
프롬프트 버전별로 이를 비교한다.

### 1.2 실험 대상
| 항목 | 값 |
|---|---|
| 요약기 | `domain/report/summarizer/ClaudeReportSummarizer` |
| 프롬프트 파일 | `src/main/resources/prompts/report-summary/{버전}.txt` |
| 모델 | `claude-sonnet-5` (Spring AI, `max-tokens: 1024`) |
| 사용자 메시지 | `다음 진료 보고서를 요약해줘.\n\n` + 보고서 본문 (코드에 고정) |
| 실험용 API | `POST /api/dev/report-summary?version={버전}` (dev 프로필 전용, 저장 없음) |

### 1.3 원칙
- **한 번에 하나의 변수만 바꾼다.** 버전 간 차이는 실험 목적의 변경 한 가지뿐이어야 한다.
- **같은 입력을 3회씩 실행한다.** LLM 출력의 무작위성을 고려한다.
- **테스트 데이터는 합성 데이터만 쓴다.** 실제 보고서는 사용하지 않는다.

## 2. 프롬프트 버전

| 버전 | 변경 내용 | 비교 대상 | 가설 |
|---|---|---|---|
| **v1** | 현재 운영 프롬프트 (한국어 지시, 퓨샷 1개) | - | 기준선 |
| **v2** | v1 을 영어로 번역 + "응답은 한국어로" 규칙 추가 | v1 | 영어 지시가 규칙 준수(지어내기 금지, null 처리)를 더 잘 지키게 한다 |
| **v3** | v1·v2 중 나은 쪽 + 퓨샷 예시를 자세하게 보강 | v1 또는 v2 | 다양한 예시가 짧은 입력에서의 왜곡·지어내기를 줄인다 |

### 2.1 v2 작성 규칙
- 지시, 규칙, 예시의 **내용은 v1 과 동일**하게 유지하고 언어만 바꾼다.
- 필드 이름(`visitPurpose` 등), `환자분`, `동행인`, 예시의 입력·출력 문장은 **한국어 그대로** 둔다.
- 규칙에 `Respond in Korean.`과 같은 한국어 응답 지시를 한 줄 추가한다.

### 2.2 v3 작성 규칙
- 퓨샷 예시는 **테스트 보고서와 다른 상황**으로 만든다 (테스트가 내과·당뇨이므로 당뇨 예시는 금지).
- 예시 2~3개를 권장한다.
    - 정보가 다 있는 경우
    - 일부 항목이 없어 **null 이 나오는 경우**
    - 키워드 위주로 짧게 쓴 입력
- 예시 외의 지시와 규칙은 비교 대상 버전과 동일하게 유지한다.

## 3. 테스트 보고서

같은 진료를 자세함만 다르게 세 번 작성했다. 핵심 사실(F1~F8)은 세 버전에 모두 들어 있다.

| 버전 | 용도 |
|---|---|
| **A. 자세한 버전** | 정답 기준. 실행하지 않는다. |
| **B. 요약 버전** | 실행 대상 |
| **C. 키워드 버전** | 실행 대상 |

### 3.1 A. 자세한 버전 (정답 기준)
```
진료 과목: 내과
진료 목적: 당뇨 정기 검진 및 지난번 혈액검사 결과 확인
진료 내용: 오늘 오전 10시에 환자분 모시고 내과에 다녀왔습니다. 대기가 40분 정도 있었는데 환자분이 조금 지루해하셨어요. 진료실에서 지난번에 한 혈액검사 결과를 들었는데, 당화혈색소가 7.8%로 지난번 7.2%보다 올랐다고 하셨습니다. 선생님 말씀으로는 혈당 조절이 지난번보다 안 좋아졌다고 하셨고, 다행히 신장 수치는 정상이라고 하셨습니다. 그래서 원래 드시던 메트포르민 500mg 하루 2번은 그대로 드시고, 다파글리플로진 10mg을 하루 1번 아침에 추가로 드시라고 하셨어요. 약은 4주분 받았습니다. 4주 뒤에 다시 오시는데, 그날은 피검사를 하니까 아침을 드시지 말고 공복으로 오전에 오라고 하셨습니다.
특이사항: 새로 추가된 약 때문에 소변을 자주 보실 수 있으니 물을 충분히 드시게 하라고 하셨습니다. 식은땀이 나거나 어지러워하시면 저혈당일 수 있으니 바로 병원에 연락하라고 하셨어요. 환자분이 요즘 떡을 간식으로 자주 드신다고 말씀드렸더니 간식은 줄이시는 게 좋겠다고 하셨습니다.
```

### 3.2 B. 요약 버전
```
진료 과목: 내과
진료 목적: 당뇨 정기 검진, 혈액검사 결과 확인
진료 내용: 당화혈색소 7.8%로 지난번 7.2%보다 올라서 혈당 조절이 나빠졌다고 하셨고, 신장 수치는 정상입니다. 메트포르민 500mg 하루 2번은 유지하고 다파글리플로진 10mg 하루 1번 아침에 추가, 4주분 받았습니다. 4주 뒤 오전에 공복으로 와서 피검사 예정입니다.
특이사항: 새 약 때문에 소변 자주 보실 수 있어 물 충분히 드시게 할 것. 식은땀이나 어지러움 있으면 저혈당 의심, 병원 연락. 떡 간식 줄이라고 하심.
```

### 3.3 C. 키워드 버전
```
진료 과목: 내과
진료 목적: 당뇨 검진, 피검사 결과
진료 내용: 당화혈색소 7.8 (지난번 7.2), 혈당 조절 악화, 신장 정상. 메트포르민 500 하루2회 유지, 다파글리플로진 10 아침1회 추가, 4주분. 4주 후 오전 공복 피검사.
특이사항: 소변 잦음 - 물 충분히. 식은땀/어지러움 시 저혈당, 병원 연락. 떡 간식 줄이기.
```

## 4. 실행 방법

### 4.1 사전 준비
1. dev 프로필로 백엔드 서버를 실행한다 (`http://localhost:8080`).
2. `src/main/resources/prompts/report-summary/` 에 실험할 버전 파일(`v1.txt`, `v2.txt`, `v3.txt`)이 있는지 확인한다.
3. 프롬프트 파일을 새로 만들거나 수정했다면 **서버를 재시작**해 리소스를 다시 반영한다.

### 4.2 사전 점검 (최초 1회)
없는 버전을 요청했을 때 에러가 나는지 확인한다. 이를 통해 `version` 값대로 파일을 읽는다는 것을 확인한다.
```bash
curl -X POST 'http://localhost:8080/api/dev/report-summary?version=v9' -H 'Content-Type: text/plain; charset=UTF-8' --data-binary '진료 과목: 내과
진료 목적: 점검
진료 내용: 점검용 입력입니다.'
```

### 4.3 B. 요약 버전 실행 (3회)
`V` 값만 바꿔서 버전별로 실행한다.
```bash
V=v1; for i in 1 2 3; do echo "== $V-B-$i"; curl -s -X POST "http://localhost:8080/api/dev/report-summary?version=$V" -H 'Content-Type: text/plain; charset=UTF-8' --data-binary '진료 과목: 내과
진료 목적: 당뇨 정기 검진, 혈액검사 결과 확인
진료 내용: 당화혈색소 7.8%로 지난번 7.2%보다 올라서 혈당 조절이 나빠졌다고 하셨고, 신장 수치는 정상입니다. 메트포르민 500mg 하루 2번은 유지하고 다파글리플로진 10mg 하루 1번 아침에 추가, 4주분 받았습니다. 4주 뒤 오전에 공복으로 와서 피검사 예정입니다.
특이사항: 새 약 때문에 소변 자주 보실 수 있어 물 충분히 드시게 할 것. 식은땀이나 어지러움 있으면 저혈당 의심, 병원 연락. 떡 간식 줄이라고 하심.'; echo; done
```

### 4.4 C. 키워드 버전 실행 (3회)
```bash
V=v1; for i in 1 2 3; do echo "== $V-C-$i"; curl -s -X POST "http://localhost:8080/api/dev/report-summary?version=$V" -H 'Content-Type: text/plain; charset=UTF-8' --data-binary '진료 과목: 내과
진료 목적: 당뇨 검진, 피검사 결과
진료 내용: 당화혈색소 7.8 (지난번 7.2), 혈당 조절 악화, 신장 정상. 메트포르민 500 하루2회 유지, 다파글리플로진 10 아침1회 추가, 4주분. 4주 후 오전 공복 피검사.
특이사항: 소변 잦음 - 물 충분히. 식은땀/어지러움 시 저혈당, 병원 연락. 떡 간식 줄이기.'; echo; done
```

### 4.5 결과 저장
- 출력은 `== v1-B-1` 같은 이름표와 함께 나온다. 이름표를 포함해 그대로 기록한다.
- 버전 하나당 결과는 6개다 (B 3회 + C 3회).
- 응답이 JSON 이 아니거나 에러가 나면 그것도 그대로 기록한다 (형식 실패로 집계).

## 5. 판정 기준

### 5.1 핵심 사실 체크리스트

| # | 핵심 사실 | 들어가야 할 필드 | 주의 깊게 볼 왜곡 |
|---|---|---|---|
| F1 | 당뇨 정기 검진, 혈액검사 결과 확인 | `visitPurpose` | |
| F2 | 당화혈색소 7.8%, 지난번 7.2%에서 **상승** | `diagnosis` | 수치 오기, 상승↔하락 반전 |
| F3 | 혈당 조절 악화, **신장 수치 정상** | `diagnosis` | 신장 정상 누락, "신장 이상"으로 왜곡 |
| F4 | 메트포르민 500mg 하루 2번 **유지** | `prescription` | 용량·횟수 변경, "중단"으로 왜곡 |
| F5 | 다파글리플로진 10mg 하루 1번 아침 **추가**, 4주분 | `prescription` | "추가"를 "변경·교체"로 왜곡, 기간 오기 |
| F6 | 4주 뒤 오전, **공복**, 피검사 | `nextVisit` | 공복 누락, 기간 오기 |
| F7 | 소변 잦음 → 물 충분히, 저혈당 증상(식은땀·어지러움) 시 병원 연락 | `caregiverNote` | 증상이나 대응 누락 |
| F8 | 떡 간식 줄이기 | `caregiverNote` | |

### 5.2 사실별 판정 (결과 1개마다 F1~F8 각각)

| 판정 | 정의 |
|---|---|
| **정확** | 사실이 의미 그대로 들어 있다. 표현이 달라도 의미가 같으면 정확이다. |
| **누락** | 입력에 있던 사실이 결과에 없다. |
| **왜곡** | 결과의 내용이 A(정답)와 다르다. 수치, 방향, 용량, 기간, 추가/교체 여부 등. |

### 5.3 결과 전체에 대한 판정 (결과 1개마다)

| 항목 | 정의 |
|---|---|
| **지어내기** | 입력(B 또는 C)에 없는 내용이 결과에 있다. A 에만 있는 내용이 나와도 지어내기다 (예: "오전 10시", "대기 40분", "지루해하셨어요"). |
| **조언 추가** | 원문에 없는 권고나 조언을 덧붙였다 (예: "운동을 권장합니다", "식단 관리가 필요합니다"). |
| **필드 오배치** | 사실이 엉뚱한 필드에 들어갔다 (예: 처방이 `diagnosis`에 들어감). 사실 자체는 정확으로 판정하고 오배치는 따로 센다. |
| **형식 실패** | JSON 이 아니거나, 잘렸거나, 에러가 났다. |

### 5.4 치명 왜곡
아래 중 하나라도 발생하면 그 버전은 **다른 점수와 관계없이 불합격**이다.
보호자가 잘못 믿으면 복약이나 내원에 직접 영향을 주는 왜곡이기 때문이다.
- 약의 **추가 ↔ 교체·중단** 혼동 (F4, F5)
- 약의 **용량·횟수** 변경 (F4, F5)
- 검사 수치의 **방향 반전** (F2)
- **다음 방문 시점** 변경 또는 **공복 조건** 반대로 기재 (F6)

### 5.5 버전별 집계

| 지표 | 계산 | 만점·목표 |
|---|---|---|
| 사실 정확 수 | 6개 결과 × 8개 사실 중 "정확" 개수 | 48 |
| 왜곡 수 | "왜곡" 판정 개수 | 0 |
| 누락 수 | "누락" 판정 개수 | 0 |
| 지어내기 수 | 6개 결과의 지어내기 건수 합 | 0 |
| 조언 추가 수 | 6개 결과의 조언 추가 건수 합 | 0 |
| 필드 오배치 수 | 6개 결과의 오배치 건수 합 | 0 |
| 형식 실패 수 | 6개 결과 중 실패 개수 | 0 |
| 일관성 | 같은 입력 3회 결과 사이에서 판정이 달라진 사실 수 | 0 |

B 와 C 를 따로 집계해 함께 기록한다. C(키워드)에서만 문제가 생기는지 볼 수 있다.

### 5.6 개선 판단 규칙
새 버전이 비교 대상 버전보다 **개선되었다**고 하려면 다음을 **모두** 만족해야 한다.

1. **가드레일 통과**
    - 치명 왜곡 0건
    - 형식 실패 0건
    - 지어내기, 조언 추가가 비교 대상보다 **늘지 않음**
2. **주지표 개선**: `왜곡 수 + 지어내기 수` 합계가 비교 대상보다 **2건 이상 감소**
    - 합계가 같거나 1건 차이면 **동등**으로 본다. 표본이 작아 1건 차이는 우연일 수 있다.
3. **보조지표**: 주지표가 동등할 때만 아래 순서로 비교한다.
    1. 누락 수가 2건 이상 감소
    2. 일관성이 좋아짐
    3. 필드 오배치 수 감소

### 5.7 판정 결과에 따른 다음 행동
| 판정 | 다음 행동 |
|---|---|
| 개선 | 새 버전을 다음 실험의 기준으로 삼는다. |
| 동등 | 기존 버전을 유지한다 (변경이 적은 쪽 선택). 필요하면 테스트 보고서를 늘려 재실험한다. |
| 악화 또는 불합격 | 새 버전을 버리고 기존 버전을 유지한다. |

## 7. 한계와 이후 과제
- 진료 상황이 1개뿐이라, 이 실험 결과가 다른 진료과나 상황에도 그대로 적용된다고 보장할 수 없다.
- 테스트 보고서에 모든 항목이 들어 있어서, **원문에 항목이 없을 때 null 로 두는지**는 검증하지 못한다.
- 이후에는 진료 상황을 늘리고, 항목이 빠진 보고서(처방 없음, 다음 방문 미정 등)를 추가한다.
- 최종 선택한 버전은 실제 보고서 작성 흐름(`POST /api/v1/applications/{id}/report`)으로 1회 확인한 뒤 운영 설정(`prompt-version`)에 반영한다.
